# SPI-X validation report

Date: 2026-11-12  
Scope: software implementation of the supplied SPI-X proposal. Physical hardware verification is excluded.

## Result

The proposal register map and the major software-verifiable capabilities are implemented. The complete `scripts/run_all_checks.ps1` run completed successfully after the register-map migration and RTL/test integration. The checks exercised APB, both SPI roles, FIFOs, interrupt/error handling, CDC event transfer, firmware API behavior, formal FIFO properties, synthesis and the iCEBreaker/MCP3008 behavioral target.

## Check results

| Check | Result | Evidence / limit |
|---|---|---|
| Python reference suite | **PASS** | 10 checks cover protocol reference behavior, the 12-register ABI against RTL and C, FIFO assumptions, and reset/event CDC structure. |
| C driver and demo | **PASS** | Strict host compiler build and C API checks pass. The transfer helper is API-tested against a memory mock; C is not co-simulated with RTL. |

Waveform assertions passed. |
| Paired controller system test | **PASS** | Fresh Verilator build links two SPI-X instances and verifies full-duplex `0xA5` / `0x3C` transfer and completion IRQs. |

## Tool anomaly and remaining scope

- **Icarus compiler process: FAIL (tool shutdown only).** It exits with Windows access violation `-1073741819` after writing an image. The script accepts only that run's fresh image; VVP executes it and the simulation plus waveform checks pass. Verilator also provides a clean simulation path.
- **Hardware test: OUT OF SCOPE.** No physical FPGA/ADC validation was requested.
- **Full static CDC/MTBF sign-off: NOT RUN.** Async FIFOs and event crossings are simulated and bounded where practical, but complete metastability analysis needs a dedicated CDC methodology and device-specific constraints. This is a production sign-off task, not a blocker to completing the requested software project.

## Reproduction

In PowerShell from the project root run `./scripts/run_all_checks.ps1`. Review the detailed ABI in [register_map.md](register_map.md) and the boundaries in [architecture_gap_analysis.md](architecture_gap_analysis.md). Generated logs and waveforms are under `work/` (the top-level VCD is generated by integrated simulation).
